每条路径分别记录实际unique miss和引用命中率；精确launch级LRU的同stamp并列选择可能使两路径miss略异。参考仍逐步max(本地计算, 本路径实测unique未命中字节/带宽)再求均值，没有max(mean)或改模拟器。direct可能重复读取引用；本表仍用共同的去重搬运乐观参考，不用重复字节抬高参考来缩小差距。

## LRU开关与batch差距的补充澄清

上表无LRU10%/30%初始远端比例，和LRU几乎100%初始远端的完整trace不构成缓存开关消融。LRU引用命中率约79%，unique页命中率约61%，是两个分母；无LRU的本地初始驻留90%也不是LRU命中率。当前R128同trace可由原始页集合直接核算：无cache需搬672.920MB/步，LRU后259.582MB/步；100GB理想逐步参考因此由6.729ms降为2.691ms，当前实测缓存路径3.290ms。距参考百分比变大不代表总时间比不开cache差，必须看同输入总耗时和移动后的参考。

R16→R128为8倍请求，纯device计算只增4.9倍（0.503→2.467ms），unique搬运约增8倍（32.44→259.58MB）。100GB0/20µs当前LRU相对差距实际由34.6%/40.4%降到22.2%/22.9%；此前“batch更大差更多”的观感混入无LRU低远端比例及不同路径。NVLink选择路径后R16差10.9%、R128差22.3%确实存在，当前尚无严格因果时间分解；理想参考不包含LRU/metadata/额外HBM写/SM竞争，不保证这些随batch扩大就全部隐藏。
