# SM 负载均衡实验

## 结论

负载均衡能改善一部分等待，但这轮没有消除 Host 与全本地的性能差距。给 Host 分配更多 CTA、让同一个 CTA 混合计算本地和 Host 数据、用满 108 个 CTA，都没有提高 25%/30% 命中的性能。

有收益的是合并调度：优先处理已经完成的 Host 分块，在其余分块仍读取、计算时提前合并。最终默认版本在 20% 命中时缩短约 1.5%～1.7%，25% 时约 1%，30% 基本不变。以 1M 为例，全本地约 27.7 µs，20%/25%/30% 分别约 30.2/34.5/40.0 µs，仍没有实现完全隐藏 Host 拉取。

## 做了哪些调整

### 调整计算 CTA 配比

测试了本地/Host 为 12/36、8/40、12/40、12/64 的分配，减少本地 CTA，把资源转给 Host。每组内部仍按行的序号轮转分配，每个 CTA 的行数最多相差一行。又测试了 12 个本地、32 个 Host、64 个合并 CTA 的分配，全部 108 个 CTA 都有工作。

这些配比均未获益。本地工作变慢后，Host 完成时间没有相应提前；增加分块还会增加 Query 读取、中间结果和合并开销。CTA 编号由 CUDA 调度到 SM，代码没有绑定固定 SM 编号。

### 在一个 CTA 内混合本地与 Host 工作

构造了 48 个混合计算 CTA，每个 CTA 都负责一份本地 KV 和一份 Host KV。使用两个 shared memory buffer，异步读取 Host 时计算本地数据，再通过在线 softmax 累积得到一份部分结果，保持 48 份中间输出。

这条路径通过了输出和 LSE 检查，但更慢。整行请求会推迟本地计算；分段请求有所改善，仍有栈访问开销，并且合并不能提前处理已经完成的本地组。它作为可复现的实验路径保留，未启用为默认路径。

### 优先合并已完成的 Host 分块

跟踪显示，Host CTA 的完成时间相差约 11～16 µs。按编号分批等待时，一个较慢的 CTA 会挡住同批已经完成的结果。新路径通过就绪位图挑选已完成的分块，每批 16 个，使用稳定的 log-sum-exp 权重逐批累积。各 head 的合并顺序可以不同，最终仍包含全部选中的 KV。

合并 CTA 有了更早可做的工作，但 GPU 读取同样的 Host 数据仍共享 PCIe 链路，这项调整无法按增加 SM 的比例缩短传输。单纯增加 CTA 或填满 SM，不能消除这个限制。

### 根据命中率选择合并路径

无条件使用分批合并会拖慢低命中率，因此默认只在至少 410 个 Host token 时使用就绪调度，对应本测试中约 20% 的命中率。低于该值保留批量合并。命中数在 kernel 内分类索引时得到，由本地第一个计算分块通过原有的 release/acquire 协议发布，不增加独立 kernel 或 CPU 预处理。

最终默认版本仍使用 16 个本地、32 个 Host、32 个有效合并 CTA。242 个寄存器，零栈空间。0% 的性能与冻结参照一致，10%/15% 的额外开销约 0.1～0.3 µs。

## 最终默认版本的性能

A100-SXM4-40GB，GPU 2，Host NUMA 1；BF16，单个 decode query，64 heads，top-k=2048，随机命中。每项均与冻结的分段直访版本配对，使用相同输入和物理 KV 分配。40 轮、8 组索引，每个 CUDA Graph 含 100 次串行调用。单位为 µs，top-k 计算不计入。

| 上下文 | baseline 20% | 就绪调度 20% | baseline 25% | 就绪调度 25% | baseline 30% | 就绪调度 30% |
|---|---:|---:|---:|---:|---:|---:|
| 128K | 30.68 | 30.16 | 34.88 | 34.53 | 40.04 | 40.00 |
| 256K | 30.68 | 30.23 | 34.97 | 34.62 | 40.22 | 40.00 |
| 512K | 30.68 | 30.16 | 34.94 | 34.49 | 40.19 | 39.99 |
| 1M | 30.70 | 30.18 | 34.92 | 34.55 | 40.12 | 39.99 |

收益较小，30% 的变化不足以说明有实质改善。25% 相比全本地仍有约 25% 的延迟增加，约 20% 的吞吐损失；30% 则约为 44% 的延迟增加、31% 的吞吐损失。不能把两种“下降 20%”标准混用。

## 其他配比的结果

下面为 1M 的代表性结果，单元格表示同轮冻结参照 → 候选耗时，单位为 µs。不同实验的绝对值不能代替配对比较。

| 方案 | 轮数 | 25% | 30% |
|---|---:|---:|---:|
| 本地 12 / Host 36 | 40 | 34.88 → 36.93 | 40.01 → 42.27 |
| 本地 8 / Host 40 | 12 | 34.87 → 37.57 | 40.03 → 41.86 |
| 本地 12 / Host 32 / 合并 64 | 12 | 34.87 → 37.00 | 40.02 → 42.92 |
| 48 个混合计算 CTA | 40 | 34.87 → 38.99 | 40.03 → 43.46 |
| 无条件优先合并，16 个分块一批 | 40 | 34.89 → 34.43 | 40.08 → 39.95 |
| 最终默认，按命中率切换 | 40 | 34.92 → 34.55 | 40.12 → 39.99 |

分阶段跟踪中，固定 16/32 配比的 Host 读入和 QK 准备在约 26.6/30.7 µs 完成，Host 计算在约 29.7/34.8 µs 完成。改成 12/36 后，没有提前。这里的准备阶段包含 QK，不是纯 PCIe 时间；跟踪使用粗粒度 globaltimer，未用于上面的性能表。

## 验证与复现

最终默认版本通过 468 项 BF16/FP16、LSE 两种底数、随机/头部/尾部布局、CUDA Graph 重放、Host 内容更新和 409/410/411 行切换边界检查。输出最大绝对误差为 0.004857，racecheck 和 synccheck 均无错误。各实验共有 728 项配对 FP32 输出检查通过。

旧的 Memcpy、原算子直访、固定分段直访路径及原有表格、figure 均保留。冻结参照是 `da4ede5f` 的算子二进制，当前默认新增合并调度；原始记录和源码快照没有覆盖。
