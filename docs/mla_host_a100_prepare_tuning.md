# A100：小 batch 准备优化与取数流水筛选（2026-10-29）

本轮增加一个显式编译选项 `FLASHINFER_HOST_BATCH_SMALL_PREPARE`，优化小 staged cache batch 的准备和扫描。**默认关闭，默认构建保留原实现。** 这样可在已验证的高延迟场景选择更快路径，同时保留物理 PCIe 的原路径。每次调用仍是一个 cooperative kernel，精确逐 launch LRU、4096 槽/请求、原始 top-k 和模拟器均保持；HiSparse 不改。

## 最终实现与验证

开关开启时，至多 32 个 query/head tile 的 staged cache 实例使用每线程一个条目的 prepare（原为八个），并用一个 warp 计算行前缀和，减少短段的填充指令与多 warp carry 同步。通用 prepare/scan/resolve/fetch 的原函数保留，小 staged 实例调用独立 helper；关闭宏时不编译这些 helper，仍调用基线函数。内部 workspace 和 Python API 没有变化。

**开启选项后 101 项完整正确性测试通过，175.76 秒。** 覆盖 FP16/BF16、64/128 头、精确 LRU、8192 槽、缓存副本、持久池跨实例切换、CUDA graph、staging 不足、padding 和空行恢复。本轮为已有边界测试新增 fetch CTA 数 1/4/16 参数，检查较长取数轮次及短尾。

## 测量范围

GPU0/1 已被其他服务占用，本轮只使用空闲的 **GPU3 A100-PCIE-40GB**。模拟链路的 near/far 为同卡不同 HBM 分配，经未改模拟器限制为 50/100 GB/s＋20 µs，另测 100 GB/s 无附加延迟和正常构建的物理 Host PCIe。**这不是物理 NVLink 测量，也不能与前几轮 SXM 双卡的绝对耗时直接比较。** `tiers.py` 仅避免同卡 VMM 映射重复加入同一访问设备；异卡和 Host 的描述符保持原样。

最终开/关对照使用同一份源码、不同编译选项和独立 JIT 目录。7 次冷启动，分段入队检查通过后保留样本，稳态取后半步逐步中位数平均。代理 trace 为 64K/32 连续位置，真实 assistant 为四段完整 64K/1024 连续 assistant 位置，MTP1/8、1/4/16/128 请求覆盖按相应矩阵保存。

下限 b 使用本卡正常构建纯 HBM 的最好实测样本；下限 a 为逐步 max(b, 去重未命中字节/设置带宽)，固定延迟不计入 a，比值不截断。完整表同时列出两下限、比值和未命中量。精确 LRU 在同一 launch 内的等时戳项允许不同淘汰顺序，因此不能假定两个版本每步字节逐字相同。

## 未采用的候选与局限

阶段插桩显示，四请求 MTP1/MTP8 的取数约在 kernel 第 11/22 µs 开始，LRU 选择约 20 µs并已与取数重叠。插桩会改变代码生成，单次调用 event 也可能包含 CPU 间隙，仅用于定位。

曾测试 16/32 行的四缓冲取数环。32 行候选在 100 GB/s＋20 µs 的完整 assistant 上快约 2%–6%，但无附加延迟的 MTP1 16 请求从 139.52 增至 160.96 µs（慢 **15.4%**），物理 PCIe 小 batch 也有约 **4.4%** 回退。因此最终源码不包含新取数环，只保留实验补丁与全部样本；不能把流水候选的较高收益写成最终选项的收益。

去掉取数环后，物理 Host MTP1 16 请求原地读仍多次出现约 6% 的慢格。一次隔离 helper 后恢复至 324.74 µs，后续完整矩阵又回到约 345 µs。隔离前后主 kernel 的反汇编指令文本相同，**没有证据认定隔离已修复问题**，也不把差异简单归为噪声。因此准备优化采用显式选项，默认保留基线；开启后仍需按实际链路和 batch 验证。原始慢格、反向复测及更快的旧版 staged 样本均保留。

## 文件与复现

最终开/关结果为 `enabled_*` / `default_*`，汇总在 [`results.md`](../temp/sim_link/tune_prepare/results.md)。`final_*` 是早期流水候选，`accepted_*` / `retained_*` 是中间版本，不能当最终源码结果。对应表为 `pipeline_results.md`、`pre_isolation_results.md`、`retained_results.md`。

`guarded_verify.py` 验证开启选项的完整测试，再运行开启/关闭全矩阵及开启后的关键场景复测；`finish_guarded.py` 保存编译器资源和压缩 SASS、生成报告并审计；`audit.py` 检查全部源码恢复补丁、结果 SHA、样本数、入队段及引用误差。`sources.py` 可从本机 git 基线和补丁恢复未跟踪的源码快照。运行前先归档既有输出、确认 GPU3 空闲，脚本拒绝覆盖 JSON。

模拟构建开启方式是在现有 `FLASHINFER_EXTRA_CUDAFLAGS=-DFLASHINFER_FAR_EMU` 后增加 `-DFLASHINFER_HOST_BATCH_SMALL_PREPARE`，并使用独立 `FLASHINFER_WORKSPACE_BASE`；正常构建只增加后一个宏。基准脚本可用 `screen.py LABEL --small-prepare --full`，关闭时省略 `--small-prepare`。

H800 原排队源码和第三轮独立快照保持；本轮只同步报告、补丁与证据，不以 A100 模拟代替 H800 验证。
