# A100 第二轮：LRU 更新重叠与小 batch 分块（2026-10-28）

在第一轮 [`mla_host_a100_100gb_tuning.md`](mla_host_a100_100gb_tuning.md) 的 `d92e7e83` 基础上继续优化。本轮主要改善 100 GB/s 下的小 batch：同参数、反向顺序重测确认 MTP8 的 1/2 请求耗时下降约 10%–11%，MTP1 四请求下降约 9%。GLM 8K 的 256 步接入中四请求下降约 12%。仍保留单 cooperative kernel 和按 launch 粒度的精确 LRU，没有改变模拟器、缓存容量或输入 trace。

## 保留的改动

1. **staged 模式的缓存映射更新移到 fetch CTA**。LRU CTA 先选淘汰槽、打本步时间戳、发布 victim；fetch CTA 在发布 staging 数据后，更新 resident/slot_page 并填入缓存。prepare 的 resident 查询已经完成，被淘汰页本步没有引用，victim 也互不重复，因此该阶段与 attention 重叠。下一次 launch 前仍保证缓存映射和字节完整。原地读的绑定时机保持。
2. **没有未命中的池跳过 LRU 扫描**，仍发布必要的就绪标志。新增“一个池全部命中、另一个连续替换”的用例，逐步验证不受影响池的槽位和所有缓存内容。
3. **LRU 的 less/equal 两次前缀扫描合并成一次**。池上限为 8192，两计数各占 16 位，前缀总和不会跨字段进位；由 equal 前缀截取 threshold 的 tie 配额，保留原先精确 LRU 语义。
4. **staged＋缓存＋host_split 的小 batch，为 Host attention 任务预留首波并行空间**。HBM 分块数上限为 `min(32, max(1, 3×grid/(4×tail_tiles)))`，再用原 cost 模型选取；不开缓存、原地读和关闭 host_split 沿用原规则。大 batch 满行的切分规则保持，部分收益来自 LRU 重叠和代码生成。

## 与上一轮推荐参数一起检查

100 GB/s＋20 µs，MTP8 的 f24/h64：2 请求 151.55→140.80 µs（−7.1%），4 请求 272.90→249.86 µs（−8.4%）；128 请求 4435.97→4422.14 µs（−0.3%，接近不变）。f16/h256 的四请求 235.01→233.47 µs（−0.7%），因此不能拿 h64 的明显改善宣称相对旧版最优参数同样提升。MTP1 f32 的四请求也只有约 0.7% 改善。

**没有隐去回退**：f24 的 MTP8 单请求 102.91→104.45 µs（慢 1.5%）；f32 的 MTP1 16 请求 167.87→169.34 µs（慢 0.9%）。PCIe 第二组 staged 的 1/4 请求各慢约 5.6%–5.8%，原地读四请求慢 6.8%；第一组对应 staged 没有回退。为此又做 9-pass 的旧→新→新→旧交替测量：f16 四请求旧版两次为 372.22 / 349.70 µs，新版为 367.62 / 345.09 µs；f8 四请求旧版 377.34 / 354.82 µs，新版 350.21 / 371.71 µs。小 batch PCIe 自身存在明显波动，**不能据此宣称稳定改善或完全无回退**，原始数据均保留。50 GB/s＋20 µs 大 batch 大体不变，小 batch 四请求 staged 约快 9%。高延迟下 MTP1 的 1/4/16 请求同参数接近不变，仍需进一步优化。

本轮有 Memcpy/Direct 计时对照的调参检查在 `results_tuned.md` 对应 JSON；普通前后表主要比较本文本身。未声明普遍击败朴素方法或已经达到纯 device 速度。

## 验证与复现

- A100 GPU0/1、NV12、NUMA0。BF16、64 头、top-k 2048、4096 槽/请求，所有前后结果分别保存每步耗时、未命中页、源码哈希和 pass 样本。
- 代理 trace：64K 上下文、总计 32 连续位置，MTP8 为 4 步、MTP1 为 32 步。GLM 数据为已经核验过的真实 8K trace、256 连续位置，**不能替代仍排队的正式 64K/1024 trace**。
- 完整正确性测试以及正向/反向对照日志、原始数据和两下限见 `temp/sim_link/tune_lru/`。两轮对照都包含 100 GB/s 的 0/20 µs、50 GB/s＋20 µs、Host PCIe、真实 GLM 8K；另外验证 f24/f32/h256 原推荐配置。H800 仍待实测。
- **79 项完整测试通过**，包括两模式的最大 8192 槽，以及一个池无未命中、另一池连续淘汰的缓存字节和映射验证。最终对照与下限/PCIe交替复核共 45 份计时 JSON、198 个批次配置，本文逐步采样行校验通过，最大绝对误差 0.006596。`manifest.json` 保存文件哈希、实测源码版本和运行覆盖。
- 初始筛选发现 KV 分块数能显著影响 staged 小 batch，但强制分块对原地读可有明显回退，最终只保留受限的 staged 规则。失败候选在 host launcher 中调用 device-only helper，导致第一次 launch 前退出；已改为读取 host 参数并重新跑全量，失败运行没有计入性能数据。
- 实验数据源代码快照和 zero-context 补丁用于还原实际测量源码；实验 `--kv-chunks` 覆盖只在应用保存的 planner 调参补丁后有效，最终正常构建没有该运行时覆盖。
