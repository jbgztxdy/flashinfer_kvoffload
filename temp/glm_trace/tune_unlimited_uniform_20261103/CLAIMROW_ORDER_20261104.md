# 认领行分配：写回负载与包顺序

范围：GPU3/A100-PCIE、NUMA1、同卡独立HBM源，BF16、64 heads、MTP8/R128/K2048、每请求LRU4096，256位置/32步冷启动。正常构建；没有把同卡HBM称为物理NVLink或可信100GB模拟。生产三header未改。测试仍是单cooperative kernel，完整QK/softmax/PV、精确LRU、每unique页真实远端读取及stage/cache必要写入均保留。

先用同一诊断二进制、两次一pass核对原全局轮转与claimrow_quota。参数fetch_ctas=23/24在私有候选中只选择策略，两个模式均为108个全计算CTA。轮转3117.760µs、认领行配额3182.176µs；各CTA平均planner耗时0.103/3.569µs，最晚planner后时点186.208/190.016µs，最后包发布1456.096/1484.576µs，计算/drain结束3107.936/3172.576µs（相对各步最早起点，32步平均）。相差64.416µs主要在准备之后出现，阶段数不是严格可相加的因果分解。同一实际库SHA、逐步原时间在claimrow_timeline_analysis.json和两份raw。

另一实际末步有177494 unique页、121494获准cache写回页。原认领行配额虽每CTA严格82/83包，获准cache页数却220–1660，CV0.2783；同一末步元数据按原轮转重新归属的CPU反事实为1002–1240，CV0.0525。实际配额CTA的获准页数与本CTA最后发布耗时Pearson约0.654，仅相关非因果。CPU反事实没有另一次GPU轮转计时，也不是硬件事务计数。输入/分析见packet_weights和claimrow_workload_analysis.json。

据此只构造一个半本地交错候选：每CTA优先保留最多floor(配额/2)个认领行包，其余包按互素步长排列并填满原严格82/83包配额。实际末步CPU反事实获准页CV从原配额0.2748降到0.1824；真正全局轮转是0.0505，模型中的zero_local_sequential不是全局轮转。原服务协议、ready epoch、LRU和字节不变。GPU两项K65/K2048数学/LSE/padding/Graph与最终全部有效cache载荷检查通过；实际8865包表与用本次rowprefix构造的CPU表逐项一致，保留4396/溢出4469，自用远端引用86388/349728=24.70%。正常三pass为3347.008/3359.360/3504.416µs，均3403.595，明显慢于旧认领行配额3200.331和近期clean3124.192。模型的写回均衡没有变成速度收益。

插桩后的交错候选单pass3353.152µs；平均CTA planner约4.783µs，最晚planner结束188.608µs，计算/drain结束3343.904µs。与旧quota时间线跨二进制，不扣减成严格单项成本；至少不能把几百微秒损失主要解释为planner。首次插桩源码在末尾把时间戳0–4覆盖为旧诊断计数，只有编译、未上GPU；原件与日志保留。修正后raw和库SHA经audit核对。

按每CTA真实包号升序做共享内存bitonic排序，保持上述owner、包数、远端读取和cache写回总量，只改变发布顺序；容量大于128包时不排序。排序网络随机1–128长度CPU检查通过（verify_interleave_sort.py，claimrow_sort_model.json），GPU两项定向检查和K65一次目标kernel racecheck通过（0 errors/0 warnings）；实际8878包表及ready epoch一致，最终cache载荷通过。三pass3224.192/3220.032/3295.552µs，均3246.592。对未排序版有明显恢复信号，但仍慢于原claimrow_quota和clean，故两个新候选均拒绝、不安装、不做100GB外推。排序版REG255/STACK16、static2304B（未排序1280B）、dynamic163072B，未把静态指令或资源变化当时间因果。

按原108包波次保持一CTA一包的离线界：该实际末步8877包中，每波次不同认领CTA平均12.54个，即使最优匹配也最多1041包/11.73%交给认领行CTA；只是末步组合上限，未实现或实测。因此不重复旧pool映射，也不据此声称局部性无价值。后续要改善全CTA unique方案，需在维持接近原波次发布时序的同时降低跨CTA等待或服务写回长尾；现有证据没有证明哪一项单独可回收。首半本地构造脚本转义错误及其下游缺include构建失败保留在failed_setup日志；全部失败、负差、源码/实际库SHA及原始步级时间保留，未改参考或模拟器。
