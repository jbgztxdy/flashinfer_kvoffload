# Separate next mechanism: resolved KV pointers in unused whole-row partial storage

This is a source-grounded design, not implemented or measured. Finish the current JQ native/cross-shape gates first; never overwrite JM or JQ inputs or a waiting plan. Production remains b6. This differs from old `prebind` (cache-map binding in fetch) and `direct_cache` (attention reading a selected cache victim): it would preserve the current staging/cache layout and simply precompute each final KV row address.

The current per-tile loader reads an encoded int32 page, selects `params.ckv` versus `params.staging`, decodes negative rows, and forms a 64-bit576-element row offset. A full8-SM partial allocation is already reserved by `_run_host_batch` (`flashinfer/mla/_core.py:975-994`): 864 partials on108SM, each64heads×512features×2B,56,623,104B. Whole-row paths do not use partial states. R128/MTP8/K2048 needs16,777,216B for one uint64 pointer per NNZ; R64/MTP8 needs8,388,608B. The existing allocation can hold them without allocation/API changes. A new dispatch must explicitly require `rows*max_kv_len*8 <= partial_capacity*64*512*sizeof(DTypeO)` using uint64 arithmetic; otherwise retain the current path. Do not assume every large shape fits.

A safe initial implementation could fill pointers after resolve/compaction and add a grid barrier, but the extra pass/barrier may erase the benefit. Source inspection shows a fused version can use existing barriers:

1. Clone the original prepare helper only for a new dedicated traits/params type. When it writes a near/cached entry to the final local position of `remap`, also store the resolved row pointer at the same index in `reinterpret_cast<uint64_t*>(params.partial_o)`. Cache hits are already encoded by prepare. The existing first grid barrier publishes these stores.
2. Clone resolve only for the new kernel. When it writes the final staged entry for a Host page, also store its staging row pointer. The full-staging dispatch requirement guarantees every Host entry is staged. Preserve all dedup/LRU `unique_pages`, `slot_pool`, `row_slot_base` and flag behavior.
3. Clone padding compaction and copy the pointer together with the int32 entry for each mover. The existing compaction explicitly copies disjoint equal-size hole/mover ranges, so the pointer copy also has no overlap hazard; every source near/cached pointer was published by prepare before resolve/compaction. The original second grid barrier publishes resolved Host pointers and compacted locals. For unique=0 and gaps=false the first barrier already suffices.
4. Keep original `remap` and ready-flag acquire reads, including flag granularity/epoch. Only the new tile-ID prefetch/load helpers use uint64 row pointers, adding the per-thread feature offset and KPE512 offset. Padding must issue no invalid global access. Do not alias or overwrite the partial storage in a tail/merge path.
5. Preserve the canonical math header and all original helper definitions literally, and use a dedicated inherited traits type to avoid the original-instruction changes seen in JM. Require34EMU/68normal exact original codegen, actual single cooperative Graph dispatch,105+4 tests including padding/eviction/zero miss/Graph/all cache payloads, source snapshots, then paired short performance against both production and the current winning math schedule. No fetch/unroll/cadence sweep.

Costs remain: extra8B/NNZ pointer writes and8B tile-ID reads versus original4B IDs; two address registers instead of one ID may spill. The original original-page readiness loads remain. This is not an established performance cause or a promised improvement. Reject if same-parameter results do not survive the overhead. Never alter the simulator, reference formula, original5304matrix or exact LRU to manufacture gains.
