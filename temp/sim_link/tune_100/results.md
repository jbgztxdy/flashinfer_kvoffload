# A100：100 GB/s 高延迟与小 batch 调优（2026-10-28）

旧版基线取 c7921958 的 kernel，16 个 fetch CTA、host_item_entries=64。新版仅改变 fetch CTA 多于 8 个时的 16/64 行搬运块选择，另扫描 fetch 数和 attention item 大小。表中最优值从列明的新配置中取，包含调参收益；同参数对照单独列出。

f 为 fetch CTA 数，h 为 host_item_entries（远端 attention 任务的目标 KV 条目数）。比较基线固定为 f16/h64，不代表旧版所有参数中的最优值；例如无附加延迟的 MTP8、4 请求，此前 f8 的结果已接近本次 f16/h256。

GPU0/1 为 A100-SXM4-40GB，NV12；模拟带宽 100 GB/s，延迟为附加值。BF16、64 头、top-k 2048、64K 上下文、4096 LRU 槽/请求；使用此前 DeepSeek-V2-Lite 代理 top-k，MTP8 为 4 步、MTP1 为 32 步，每种配置 7 次冷启动，取各步中位数后对后一半步平均。GLM 正式 64K trace 仍排队。

b = 正常构建、纯 HBM FA2 attention 的最好实测样本；a = 逐步 max(b, 本文去重后未命中页 × 1152 B / 模拟带宽) 的稳态平均。a 是未计依赖延迟的乐观下限。比值直接计算，未截断。朴素方法 CPU LRU 不计时；本次远端为 peer GPU，其 gather 计时。

## 原始结果与验证

最终核查 13 份计时 JSON、63 个批次配置；本文每步采样行正确性通过，最大绝对误差 0.006007。

`verification_runs.json` 保存最终命令和源码哈希；同目录保留初始扫描及未采用方案的数据。

未采用：四级 fetch 流水在一些小 batch 有收益，但固定 f16 时大 batch 回退；单 warp 前缀扫描收益不足；缩小 cooperative grid 损失 attention 并行度。候选补丁和计时数据均保留，未进入最终 kernel。

50 GB/s＋20 µs 的新版检查保存为 `verify_final_mtp8_g50_l20000.json`，未据其声明达到纯 device 性能。
